# 1. O que são portas

Porta é um número que identifica *qual serviço/processo* dentro de uma máquina deve receber os dados — o IP leva até a máquina certa, a porta leva até o serviço certo dentro dela. Vai de `0` a `65535`.

## 1.1 Organização

Sem porta, uma máquina só poderia rodar **um único serviço de rede por vez**, já que o IP sozinho não diferencia processos dentro da mesma máquina.

Com porta, vários serviços coexistem no mesmo IP, cada um "escutando" (bind + listen) na sua própria porta:

```
192.168.0.10:22    → SSH
192.168.0.10:80    → servidor web
192.168.0.10:3306  → MySQL
```

O sistema operacional recebe o pacote, olha a porta de destino, e entrega pro processo que fez bind naquela porta. Por isso é possível ter cloud compartilhada, microsserviços e múltiplos sites numa mesma máquina física.

## 1.2 Conexões múltiplas

A porta de **destino** identifica o serviço, mas quem permite múltiplas conexões simultâneas ao mesmo serviço é a porta de **origem** — escolhida aleatoriamente pelo seu sistema a cada nova conexão.

Toda conexão é identificada por 4 valores (a "4-tupla"):

```
IP origem : porta origem  ↔  IP destino : porta destino
```

Duas abas do mesmo site geram duas conexões com o **mesmo destino**, mas **origens diferentes**:

```
Aba 1: 192.168.0.10:51001  ↔  142.250.219.14:443
Aba 2: 192.168.0.10:51002  ↔  142.250.219.14:443
```

É essa combinação completa que o SO usa pra separar o tráfego de cada conexão — não só o número da porta de destino sozinho.

# 2. Portas conhecidas

Faixa `0–1023`, reservada por convenção (IANA) para serviços padrão. Não é uma trava técnica — é padrão de mercado que todo mundo segue pra evitar confusão.

## 2.1 SSH — porta 22

Acesso remoto seguro a terminais de outra máquina. Protocolo binário, com handshake de troca de chaves criptográficas antes de qualquer dado real trafegar. Usado pra administrar servidores remotamente (Linux principalmente).

## 2.2 HTTP — porta 80

Protocolo de transferência de páginas/dados web, em **texto plano** (sem criptografia). Hoje é usado principalmente como "porta de entrada" que redireciona automaticamente para HTTPS.

## 2.3 HTTPS — porta 443

Mesmo protocolo HTTP, mas envelopado em **TLS** — criptografa o conteúdo da comunicação. É o padrão atual pra praticamente qualquer site, já que protege dados como senhas e cookies de serem lidos por quem intercepta o tráfego.

# 3. Softwares que escutam portas

## O que são

Qualquer programa que faz **bind** numa porta e entra em modo **listen**, ficando esperando conexões chegarem. Pode ser um servidor web, um banco de dados, uma API, ou até um script simples seu.

## Como funcionam

1. **bind()** — o processo reserva a porta pra si junto ao sistema operacional
2. **listen()** — avisa que está pronto pra aceitar conexões
3. **accept()** — quando uma conexão chega, o SO entrega ela ao processo, que passa a trocar dados com aquele cliente específico

Regra importante: **só um processo pode fazer bind numa mesma porta/IP ao mesmo tempo** — daí o erro clássico `Address already in use` quando dois serviços tentam usar a mesma porta.

Por isso, quando se quer rodar várias aplicações na mesma porta pública (80/443), usa-se um **proxy reverso** (ex: Nginx) — só ele escuta a porta externa de fato, e repassa internamente pra cada aplicação (rodando em portas internas, ex: 3000, 5000, 8000) com base no domínio ou path da requisição.

Para cada linguagem, exemplos de software/bibliotecas que fazem bind em portas — geralmente dividido entre **framework** (lida com rotas/lógica da aplicação) e **servidor** (efetivamente aceita as conexões TCP).

| Linguagem | Exemplo 1 | Exemplo 2 | Exemplo 3 |
